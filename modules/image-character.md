# Image Annex · Character / Recurring Face
Loaded together with `image.md` (Parts A, B and E; Part C when the scene is advertising) and with §1 of `image-product.md` (neutral background of references). Law 5: a real person only with recorded authorization.

## Character / Recurring Face / 360 Character (References → Reconstruction → Approval)

Used when the piece shows **the same person** recurrently (founder, specialist, doctor, speaker, spokesperson) or a created character (mascot, illustrated). Everything specific to the person lives exclusively in `[Cliente]\_DESIGN\Personagens\[Pessoa]\PERSONAGEM_[PESSOA].md` and `Referências\`.
**Technical name and triggers:** `Character Turnaround Sheet` (or `Model Sheet` / `Character Reference Sheet`); variant `Expression Sheet`. Activates with `/360-character`, `360 character`, `character turnaround`, `model sheet`, `expression sheet`.

### 1. Authorization and Limits
- A real person's face in AI requires **recorded authorization** in the dossier (`Autorização: date · who · file`). Without a record: generate only as an internal test and warn the user.
- Vetoes in `design_system.md` prevail until an explicit user order (record the decision).
- Forbidden: celebrity/external public figure, minor, or using a generated image as a real testimonial, a true clinical/technical act or an endorsement that did not occur.

### 2. Building the Standard (once per person)
Also apply U12 to `360 character`, `character turnaround` and `character multiview`: originals and official/trustworthy sources of the same person take priority; generated views, even approved, are lower-weight support. Consult the relevant local and official sources before reconstructing the missing angles.
1. **Selection of 4–8 original photos** (`Originais\[Pessoa]\`, untouched): neutral frontal, smiling frontal, close-up, ¾ left/right, half body, seated (sharp eyes, even light, no sunglasses, filter or hand on the face). **Master** = frontal with the best light.
2. **`_ref` package + Atlas:** save 2048 px copies (`_ref`) in `_DESIGN\Personagens\[Pessoa]\Referências\` + sheet `atlas_[pessoa].jpg` for human inspection only (never send the whole atlas as a single reference so as not to dilute traits). Generated reference views (frontal, ¾, profile) follow the **neutral colorless background** rule of `image-product.md` §1; scenes of the person are outputs and go to `Imagens\IA\`.
3. **Facial checklist + Corrective rules + Descriptor (EN):** number observable traits (hair/baldness, beard/mustache and gray pattern, eyebrows, eyes, face shape/jaw, nose, skin tone/texture, ears, build, base expression), record corrective rules against model deviations and close with the descriptor in English + `"keep his/her facial features, bone structure and skin texture 100% identical to the reference photos"`.

4. **360 reconstruction and approval:** when the 360 is requested, complete the missing views by AI using the master and the best existing references; do not require a real photo of each angle to begin. Generate front, back, sides and ¾ left/right, as individual files and an inspection board with consistent neutral background, light and scale. Preserve documented face, hair, skin, build and details; separate inferences from observed traits. Mark `_gerada`, review and iterate through the creative cycle (`delivery.md` §2); only after approval incorporate as synthetic support into the package. Do not use a generated view to override identity proven in an original. The authorizations and limits of §1 still apply.
   - **Board formats:** full body standing, same panel height in all views, no text in the image; the character in image 1 is declared the only one in the scene, and hair, clothing, footwear and accessories are listed as identical in all views. For a recurring close-up (face highlighted), add a straight frontal of the face and an exact profile. Character for 3D modeling: neutral pose with arms apart, orthographic views.
   - **Identity library:** the hero view (full body, neutral, plain background) is the anchor. Each view goes through the sieve before entering `Referências\` (two attempts without improvement = measure the output, proof 3 of `delivery.md` §2), with the angle label in the name; an off-model view contaminates everything that comes after. In scenes, send the hero + 2 or 3 approved views, not the board. Redesign of the character = new hero approved first; only then do the old views go to `Referências\_antigas\`, never mixed.
5. **Expression Sheet:** 6–9 expressions of the same person, same framing, light and background; one call per expression (U12), grid assembly afterward. Two possible inputs: a named list of expressions, or an image of poses/expressions + an identity image, declaring in the prompt which is which, because the generator swaps the roles if the order is not stated. Transferring a single expression follows the same principle (image 1 = person, image 2 = expression only). Real person: the expression cannot suggest speech, emotion or an act that compromises their image (§1).

### 3. Execution, Verification and Approval
- Use generators with image-reference support: Antigravity / Nano Banana Pro (up to 14 indexed references), GPT Image in edit mode, IDE subagent, or local engine with `--ref` (what `local_engine.py` installs is FLUX.2 klein 4B; FLUX Kontext and Qwen-Image-Edit only if the user already has them in ComfyUI), sending master + closest angle, 3–4 photos. A text-only generator does not count: describing the face does not preserve the face; without a reference-capable tool, say so, deliver the ready prompt and stop. PuLID/InstantID (local identity) or LoRA only for a character recurring across many pieces: it is the last resort, high cost, and face weights (insightface, InstantID) usually have research-only licenses, so check before using in client work. In the prompt, describe **only what changes** (setting, light, pose, framing) + repeat the descriptor 1×. Never position text over the face.
- **Several references with roles** (including two or more people in the same scene): general rule in Part E of `image.md`.
- **Locked pose (engine with control map):** pose or gray 0.8–0.9; contour, depth or tile ~0.7; useful range 0.3–0.8; above 0.9 gets rigid. Ending the control at around 65% of the process locks the composition early and frees the detail.
- **Character in video:** reference-to-video with the hero and approved views, without redescribing the character in the prompt; check frames as in U12.
- **Created character (mascot, illustrated):** test reading in three layers, silhouette, then color, then detail, at small size and in close-up. A silhouette not recognizable in solid black fails before finishing.
- Compare result × master item by item of the checklist. If it deviates, diagnose the cause and choose between reinforcing the corrective rule, using a cleaner reference/at the same angle or editing the needed region. Continue while there is progress without compromising identity; stop if the tool blocks or new attempts do not improve the result. Two attempts without improvement = measure the output before the third (`delivery.md` §2, proof 3).
- **Initial approval:** approval of the 360 board does not replace scene approval. Validate 3 scenes (neutral frontal, smiling ¾, seated half body) in the client's KV before releasing for scaled production.
